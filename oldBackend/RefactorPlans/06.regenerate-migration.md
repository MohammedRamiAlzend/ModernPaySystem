# Step 6: Regenerate Transaction Migration

After all entity and DbContext changes, regenerate the EF Core migration to reflect the clean state.

## 1. Delete the existing migration

Remove the migration that was generated during the `.Ignore()` pass:

```bash
Remove-Item -Path "src\Modules\TransactionSystem\ModernPaySystem.Module.Transaction.Infrastructure\Persistence\Migrations\*" -Recurse -Force
```

Or use `dotnet ef migrations remove` if it's the active migration:

```bash
dotnet ef migrations remove --project src\Modules\TransactionSystem\ModernPaySystem.Module.Transaction.Infrastructure
```

## 2. Generate new migration

```bash
dotnet ef migrations add InitialCreate --project src\Modules\TransactionSystem\ModernPaySystem.Module.Transaction.Infrastructure
```

## 3. Verify what the migration creates

Inspect the generated `Up()` method to confirm:

| Expected | Tables |
|----------|--------|
| Transaction tables | `Requests`, `RequestTemplateValues`, `RequestRelations`, `RequestAttachments`, `Responses`, `ResponseAttachments`, `Templates`, `TemplateDepartmentOwnerships`, `UserTemplateOwnerships`, `RequestTransactions`, `RequestTransactionAttachments`, `RequestAuditLogs`, `InputValues` |
| Shared tables owned by Transaction | `Attachments`, `LookUpFields`, `LookUpFiledValues` |
| If Option A | `Requests.ReadOnlyUsers` → JSONB column (not a separate table) |
| If Option B | `RequestReadOnlyUsers` join table |
| **NOT present** | `Users`, `Departments`, `Roles`, `PermissionEntities`, `SubSystemUsers`, or any Identity-owned table |

## 4. Apply migration

```bash
dotnet ef database update --project src\Modules\TransactionSystem\ModernPaySystem.Module.Transaction.Infrastructure
```

## 5. Build and verify

```bash
dotnet build ModernPaySystem.slnx
```

Should produce 0 errors. If there are errors, they are likely in service `.Include()` calls referencing removed nav properties — fix by removing those `.Include()` chains (nav properties no longer exist for EF to include).
