# Step 4: Inject IIdentityUnitOfWork for Cross-Module Data Access

Inject `IIdentityUnitOfWork` into Transaction services that need to read User or Department data instead of relying on removed navigation properties.

## Project Reference

Add a project reference from `ModernPaySystem.Module.Transaction.Infrastructure` to `ModernPaySystem.Module.Identity.Application` in the `.csproj`:

```xml
<ProjectReference Include="..\..\IdentitySystem\ModernPaySystem.Module.Identity.Application\ModernPaySystem.Module.Identity.Application.csproj" />
```

> **Alternative**: If the Boot project handles DI wiring, add the reference there and register cross-module services in the Boot `Program.cs`. The cleaner approach is Transaction.Infrastructure referencing Identity.Application directly (Identity.Application has no DB dependencies — only interfaces like `IRepositoryBase`).

## Service Changes

### `TemplateService.cs`

**Need:** Department name for Template DTOs (if `DepartmentName` is wanted on `TemplateDto`).

**Current approach:** `TemplateDto` has `DepartmentId` (Guid) but no Department name. If Department name is needed, add `IIdentityUnitOfWork` and resolve it:

```csharp
public class TemplateService(
    ITransactionUnitOfWork unitOfWork,
    IIdentityUnitOfWork identityUnitOfWork,
    ...) : ITemplateService
```

In methods that need Department info:
```csharp
var department = await identityUnitOfWork.Departments.GetByIdAsync(template.DefaultReceiverDepartmentId);
```

> **Note:** TemplateDto currently does not expose DepartmentName. Only add if the frontend requires it.

### `ResponseService.cs`

**Need:** Department name for `ResponseDto.DepartmentName`.

**Current code:** `Response.ToDto()` hardcodes `DepartmentName = "Unknown"` (line 27 of Response.cs).

**Fix in ResponseService:** After fetching Responses, resolve Department names. If Requester's department name is desired:

```csharp
// In GetPagedAsync or wherever ToDto() is called:
var responseDtos = pagedResponses.Value!.Items.Select(r => {
    var dto = r.ToDto();
    // Resolve department name from identity module
    var requesterDept = await identityUnitOfWork.Departments.GetByIdAsync(/* departmentId from request? */);
    dto.DepartmentName = requesterDept?.Name ?? "Unknown";
    return dto;
}).ToList();
```

> **Simplify:** If `RespondedByUserId` is enough context, pass `DepartmentName` as a parameter rather than doing per-item lookups.

### `RequestService.cs`

**Need:** User names for `RequestDto.Requester` / `RequestDto.Approver` (if UserDto data is needed on the DTO).

**Current state:** `Request.ToDto()` has:
```csharp
Requester = this.Requester?.ToDto(),
Approver = this.Approver?.ToDto(),
```

**Fix:** Remove these lines from `ToDto()` (handled in Step 5). In the service layer, resolve user names separately if needed. The `RequestDto.Requester` and `RequestDto.Approver` can be removed from the DTO or populated via separate identity calls:

```csharp
var requester = await identityUnitOfWork.Users.GetByIdAsync(request.RequesterId);
var approver = await identityUnitOfWork.Users.GetByIdAsync(request.ApproverId);
requestDto.Requester = requester?.ToDto();
requestDto.Approver = approver?.ToDto();
```

### `RequestTransactionService.cs`

**Need:** User name for `CurrentUserHolderId`.

**Current state:** `RequestTransaction.ToDto()` does NOT map `CurrentUserHolder` to a user DTO — only outputs `CurrentUserHolderId` (Guid). No change needed unless user name is required.

### `ReportService.cs`

**Need:** User/Department names for report DTOs.

**Current state:** `ReportService` previously had `.ThenInclude(r => r.Requester)` removed. It now needs to fetch user names via `identityUnitOfWork.Users`.

Example:
```csharp
var user = await identityUnitOfWork.Users.GetByIdAsync(auditLog.UserId);
```

### `RequestAuditService.cs`

**Need:** User name for audit log entries.

**Current state:** No user name mapping exists. Fix similarly to ReportService above.

### `DepartmentService.cs`

**Need:** This is the Transaction module's `IDepartmentService` wrapper. It currently may use nav properties to Department entity.

> **Note:** Check if Transaction's `DepartmentService` still exists. If it delegates to identity module calls, it should now use `IIdentityUnitOfWork.Departments` directly.

## Registration

In `TransactionModuleRegistration.cs`, register `IIdentityUnitOfWork` by calling the Identity module's registration:

```csharp
// Transaction module registration
services.AddScoped<IIdentityUnitOfWork>(sp => 
    sp.GetRequiredService<IIdentityUnitOfWork>());
```

Or ensure Identity module is registered before Transaction module in `Program.cs`:

```csharp
builder.Services.AddIdentityModule(builder.Configuration);
builder.Services.AddTransactionModule(builder.Configuration);
```
