# Step 2: Clean TransactionDbContext

After removing nav properties from entities, remove all `.Ignore()` calls and the config for `DepartmentTemplateNumber.Department`. Nav properties no longer exist, so EF Core has nothing to ignore.

## File: `TransactionDbContext.cs`

### Remove the entire `.Ignore()` block (lines 30-55)

Delete lines 30-55:
```csharp
// -----------------------------------------------------------------
// Cross-module navigation properties — .Ignore() to avoid FK
// conflicts with IdentityDbContext (which owns Departments, Users,
// Roles, PermissionEntity, SubSystemUser).
// Only scalar FK properties (DepartmentId, UserId, etc.) are stored.
// -----------------------------------------------------------------
modelBuilder.Entity<Template>()
    .Ignore(t => t.VisitedByUsers);

modelBuilder.Entity<Request>()
    .Ignore(r => r.Requester)
    .Ignore(r => r.Approver)
    .Ignore(r => r.ReadOnlyUsers);

modelBuilder.Entity<RequestTransaction>()
    .Ignore(rt => rt.CurrentUserHolder);

modelBuilder.Entity<RequestAuditLog>()
    .Ignore(e => e.User);

modelBuilder.Entity<TemplateDepartmentOwnership>()
    .Ignore(to => to.Department);

modelBuilder.Entity<DepartmentTemplateNumber>()
    .Ignore(dtn => dtn.Department);
```

### If Option A was chosen for `ReadOnlyUsers` in Step 1

Add a value converter for `Request.ReadOnlyUsers` after line 106 (after the Request → Response config) or in the `Request` config block:

```csharp
modelBuilder.Entity<Request>()
    .Property(r => r.ReadOnlyUsers)
    .HasConversion(
        v => System.Text.Json.JsonSerializer.Serialize(v, (System.Text.Json.JsonSerializerOptions?)null),
        v => System.Text.Json.JsonSerializer.Deserialize<ICollection<Guid>>(v, (System.Text.Json.JsonSerializerOptions?)null) ?? [])
    .HasColumnType("jsonb");
```

### Keep everything else

All remaining configs (lines 60-202) stay as-is — they configure intra-module relationships that are valid.
